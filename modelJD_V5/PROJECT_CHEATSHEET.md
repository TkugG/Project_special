## 🧠 ส่วนที่ 1: โพยจับคู่ "ถามเรื่องนี้ $\rightarrow$ ในหัวนึกถึงสิ่งนี้"

| ถ้าถูกถามเรื่อง... | ในหัวให้ดึงคำตอบนี้ขึ้นมาทันที | คำอธิบายเสริมแบบภาษาพูด (เข้าใจง่าย) |
| :--- | :--- | :--- |
| **ข้อมูล / ตำแหน่งงานมาจากไหน?** | **ชุดข้อมูลมาตรฐานหลักสูตร 240 งาน + งานจริง 13 งาน (รวม 253 งาน)** | ใช้ชุดข้อมูลอิงกรอบสมรรถนะหลักสูตร IT (Curriculum Benchmark) 240 ตำแหน่ง (กลุ่มละ 30 งาน) ผสานกับกรณีศึกษางานจริงจากตลาดไอทีไทย 13 ตำแหน่ง เพื่อให้สะท้อนทักษะวิชาชีพจริงและข้อมูลกระจายตัวสมดุล |
| **คลังคำศัพท์ทักษะ** | **คลังคำศัพท์ไอทีมาตรฐาน 1,784 คำ** | สกัดมาจากชุดข้อมูล Kaggle และงานไทย ทำหน้าที่เป็น "พจนานุกรมคำศัพท์ไอที" เพื่อใช้ตรวจจับและแนะนำทักษะที่ถูกต้อง |
| **ทักษะที่แสดงบนหน้าเว็บ** | **216 ทักษะยอดนิยมในตลาดไทย** | เพื่อไม่ให้ผู้ใช้ตาลาย หน้าเว็บจะดึงเฉพาะทักษะที่มีตำแหน่งงานจริงในไทยรองรับมาให้เลือก 216 ตัว |
| **การกรอกคำ / กันคนพิมพ์มั่ว** | **กล่อง Autocomplete Tag (บังคับเลือกจากชิป)** | ผู้ใช้พิมพ์แล้วจะมีตัวเลือกโผล่ขึ้นมาให้กดเลือกเป็นชิป ไม่ได้ให้พิมพ์ข้อความอิสระตามใจชอบ ระบบจึงไม่เจอคำแปลกปลอม |
| **การตัดคำ / ตัวย่อ (Synonyms)** | **พจนานุกรมจับคู่คำพ้อง (Dictionary)** | มีระบบจับคู่ เช่น พิมพ์ `k8s` หรือ `js` ระบบจะเข้าใจอัตโนมัติว่าคือ `kubernetes` และ `javascript` |
| **อักษรพิเศษ C++, C#, .NET หายไหม?** | **การล็อกคำชั่วคราว (Lock & Restore)** | ก่อนล้างสัญลักษณ์พิเศษ ระบบจะล็อกคำพวกนี้ไว้ก่อน พอล้างจุดหรือขีดเสร็จค่อยปลดล็อกคืน ทำให้เครื่องหมายสำคัญไม่หลุดหาย |
| **แปลงข้อความเป็นตัวเลขก่อนเข้า AI** | **ตารางคะแนนน้ำหนักคำ (TF-IDF)** | คำนวณว่าทักษะไหนเป็นทักษะเฉพาะทาง และทักษะไหนเป็นคำทั่วไป เพื่อแปลงรายการทักษะให้กลายเป็นตัวเลขที่ AI คิดคำนวณได้ |
| **โมเดล AI / ทำนายสายงาน** | **Logistic Regression (หา % ของ 8 สายงาน)** | เปรียบเหมือน "อาจารย์แนะแนว" ที่คำนวณออกมาเป็นเปอร์เซ็นต์ว่า ทักษะแบบนี้มีโอกาสตรงกับสายงานไหนมากที่สุดใน 8 สาย |
| **โมเดลแอบจำข้อสอบไหม? (Data Leakage)** | **ลบคอลัมน์ "ชื่อตำแหน่งงาน" ออกตอนสอน AI** | ตัดชื่อตำแหน่งทิ้งทั้งหมด ให้ AI เห็นเฉพาะ "รายการทักษะล้วนๆ" เพื่อบังคับให้มันเรียนรู้จากทักษะจริง ไม่ใช่จำชื่อตำแหน่ง |
| **ความแม่นยำ 98% / ตรวจสอบยังไง?** | **หั่นข้อมูลสลับสอบ 5 รอบ (5-Fold Cross-Validation)** | แบ่งข้อมูลเป็น 5 ส่วนเท่าๆ กัน เอา 4 ส่วนไปสอน อีก 1 ส่วนไปสอบ แล้วสลับกันจนครบ 5 รอบ ผลเฉลี่ยออกมาแม่นยำเกือบ 98% |
| **จุดที่โมเดลยังสับสน (Confusion Matrix)** | **Network ปนกับ Cloud/Security (4 งาน) และ Specialist ปนกับ Dev (1 งาน)** | เกิดจากทักษะคาบเกี่ยวกันจริง (Interdisciplinary): Network กับ Cloud ใช้ Linux/Firewall เหมือนกัน ส่วน Specialist กับ Dev ใช้ Python/Docker ในงาน Data Pipeline เหมือนกัน (สับสนเพียง 5 จาก 253 งาน หรือ 1.98%) |
| **สูตรคำนวณคะแนนงาน (Match Score)** | **คะแนนผสม 3 ส่วน รวมได้ 100% พอดี (50 : 30 : 20)** | 1) ทักษะตรงเป๊ะ 50% + 2) บริบทคำศัพท์ TF-IDF Cosine 30% + 3) ความน่าจะเป็นของสายงานจาก ML (Softmax Prob) 20% รวมกันได้ 100% พอดี ควบคุมขอบเขตคะแนนไม่ให้ล้น และป้องกันไม่ให้โมเดลพาคำตอบพังแบบลูกโซ่ (Cascading Error) |
| **ทักษะที่ตรง กับ ทักษะที่ยังขาด** | **การเอาเซตมาลบกัน (Set Difference)** | ทักษะที่เรามีตรงกับงาน = ชิปสีเขียว / ทักษะที่งานต้องการแต่เรายังไม่มี = ชิปสีเทา (สิ่งที่ต้องไปเรียนเพิ่ม) |
| **ทำไมระบบประมวลผลเร็วมาก (3-4 มิลลิวินาที)** | **แคชข้อมูลไว้ในแรม (In-Memory Cache)** | โหลดข้อมูลตำแหน่งงาน 253 งานขึ้นมารอไว้ในแรมตั้งแต่เปิดเครื่อง เวลาค้นหาจึงคำนวณในแรมทันที ไม่ต้องเสียเวลาอ่านฮาร์ดดิสก์ใหม่ |
| **ทำไม Top 5 ไม่เจองานซ้ำ / บริษัทเดิม** | **ตัวกรองความหลากหลาย (Diversity Filter)** | มีกฎห้ามตำแหน่งงานชื่อซ้ำกันเกิน 2 ที่ใน Top 5 เพื่อให้ผู้ใช้เห็นทางเลือกที่หลากหลาย ไม่ใช่เจอแต่งานชื่อเดิม |
| **ถ้าไม่เลือกทักษะแล้วกดค้นหา** | **ระบบแจ้งเตือนเตือนสติ (Error Handling / SweetAlert)** | มีระบบดักไว้ แจ้งเตือนสวยๆ ให้ผู้ใช้ใส่ทักษะก่อน ระบบไม่พัง ไม่อืด และไม่ขึ้นจอขาว |

## 💡 ส่วนที่ 2: สิ่งที่ควรรู้เกี่ยวกับโครงงานนี้ (เข้าใจภาพใหญ่แบบไม่ต้องแตะโค้ด)

### 1. ปัญหาจริงที่ทำให้เกิดโปรเจกต์นี้ขึ้นมา (The Problem)
* **เด็กไอทีมักมีคำถามในหัว:** *"เรียนมาตั้งหลายอย่าง สรุปแล้วสกิลที่มีตอนนี้ เหมาะจะไปสมัครงานตำแหน่งอะไร?"* หรือ *"อยากทำงานตำแหน่งนี้ แต่ไม่รู้ว่าตัวเองขาดสกิลอะไรอีกบ้าง?"*
* **ประกาศรับสมัครงานในตลาดเขียนไม่เหมือนกันเลย:** บริษัท A เรียก `Frontend Developer`, บริษัท B เรียก `Web UI Specialist`, บริษัท C พิมพ์ตัวย่อ `ReactJS/NextJS` ทำให้นักศึกษาค้นหางานยากและประเมินตัวเองไม่ถูก
* **ระบบนี้เลยเกิดมาทำหน้าที่ 2 อย่างพร้อมกัน:**
  1. **เป็นอาจารย์แนะแนว:** ดูสกิลรวมๆ แล้วบอกว่าเราเหมาะกับสายอาชีพไหนตามหลักสูตร มคอ.2
  2. **เป็นกระจกส่องตัว:** กางประกาศงานจริงในไทยมาเทียบให้ดูว่าตรงกี่เปอร์เซ็นต์ และมีสกิลไหนที่ต้องไปอ่านหนังสือเพิ่ม

### 2. ทำไมต้องใช้กรอบ "8 กลุ่มอาชีพ มคอ.2"?
มคอ.2 คือกรอบมาตรฐานหลักสูตรระดับอุดมศึกษาของกระทรวง อว. ที่กำหนดว่าคนจบปริญญาตรีสาขาไอที ควรทำงาน 8 ด้านนี้ได้:
1. **8.1 เจ้าหน้าที่คอมพิวเตอร์ (IT Support):** ฮาร์ดแวร์, ซ่อมบำรุง, Helpdesk, แก้ปัญหาระบบทั่วไป
2. **8.2 ผู้ดูแลระบบเครือข่าย (Network Engineer):** เราเตอร์, สวิตช์, Cisco, Firewall, สายแลน, เซิร์ฟเวอร์
3. **8.3 นักพัฒนาและออกแบบสื่อผสม (Multimedia Designer & Developer):** กราฟิก, วิดีโอ, โมชัน 2D/3D, เกม, UI/UX Prototype *(เน้นงานสื่อสร้างสรรค์ ไม่ใช่เขียนโค้ดเว็บ)*
4. **8.4 นักจัดการโครงการสารสนเทศ (IT Project Manager):** วางแผน, คุมงบ, จัดคิวงาน, Agile, Scrum, Jira
5. **8.5 นักวิเคราะห์และออกแบบระบบงาน (System Analyst - SA):** คุยกับลูกค้า, วาดผังระบบ UML, ER-Diagram, เขียนข้อกำหนด SRS
6. **8.6 นักพัฒนาซอฟต์แวร์ (Software Developer):** โปรแกรมเมอร์, เขียนโค้ด Backend/App, API, Database, Docker
7. **8.7 นักออกแบบและพัฒนาเว็บไซต์ (Web Designer & Developer):** สร้างเว็บ, เขียน HTML/CSS/JS, WordPress, Tailwind, ทำเว็บให้เปิดในมือถือสวยงาม
8. **8.8 ผู้เชี่ยวชาญด้านเทคโนโลยีสารสนเทศ (Specialized IT):** งานเทคโนโลยีขั้นสูง เช่น ปัญญาประดิษฐ์ (AI), วิทยาการข้อมูล (Data Science), ความปลอดภัยไซเบอร์ (Cybersecurity)

### 3. ประเด็นเด็ด: ทำไมสาย 8.3 (สื่อผสม) กับ 8.7 (เว็บไซต์) ต้องแบ่งเส้นให้ชัด?
* **เรื่องตลกในอดีต:** ยุคก่อนคำว่า "สื่อผสม" คือทำแผ่น CD-ROM หรือตัดต่อวิดีโอ ส่วน "เว็บไซต์" คือทำเว็บหน้าเดียว แต่ปัจจุบันทั้งสองสายดันใช้ Figma และ UI/UX เหมือนกัน
* **วิธีแก้ในระบบของเรา:**
  * **8.3 สื่อผสม:** ให้เน้นงาน **ครีเอทีฟล้วนๆ** เช่น Figma, Photoshop, Illustrator, Premiere Pro, After Effects, 3D Blender, Unity ทำเกม
  * **8.7 เว็บไซต์:** ให้เน้นงาน **เขียนโค้ดหน้าเว็บ** เช่น HTML5, CSS3, JavaScript, WordPress, Tailwind
  * **ผลลัพธ์:** AI จะไม่สับสน ถ้ามีสกิลตัดต่อวิดีโอ/ทำเกม จะพุ่งไป 8.3 ทันที แต่ถ้ามีสกิลเขียนเว็บ จะพุ่งไป 8.7 ทันที

### 4. สถาปัตยกรรมทำงานยังไง? (เล่าแบบเปรียบเทียบในชีวิตจริง)
ระบบเราทำงานเป็น 3 ด่านเหมือนการเดินเข้าบริษัทจัดหางาน:

1. **ด่านที่ 1 — ประชาสัมพันธ์คัดกรองคำศัพท์ (Normalization Layer):**
   * เหมือนมีล่ามคอยตรวจเอกสาร ถ้าผู้ใช้เขียนภาษาพูด เช่น `js` ล่ามจะแก้เป็น `javascript` หรือเขียน `k8s` ล่ามจะแก้เป็น `kubernetes` ให้ข้อมูลสะอาดก่อนเข้าห้องสัมภาษณ์
2. **ด่านที่ 2 — อาจารย์แนะแนวประเมินสายงาน (Logistic Regression Classifier):**
   * อาจารย์จะเอาสกิลของผู้ใช้มาประเมิน แล้วเคาะเป็นตัวเลขเปอร์เซ็นต์ทันทีว่าผู้ใช้คนนี้ มีแววจะไปรุ่งในสายไหนมากที่สุดในบรรดา 8 สายงาน มคอ.2
3. **ด่านที่ 3 — พี่ HR แมตช์งานจริงพร้อมสรุป Skill Gap (Content-Based Matching):**
   * กางแฟ้มประกาศรับสมัครงานจริงในไทย 253 งาน แล้วเอาไม้บรรทัดมาทาบดูว่า:
     * มีสกิลไหนตรงกันบ้าง $\rightarrow$ แสดงเป็น **ชิปสีเขียว (Matched Skills)**
     * สกิลไหนที่งานอยากได้แต่เรายังไม่มี $\rightarrow$ แสดงเป็น **ชิปสีเทา (Skill Gap ที่ต้องพัฒนาเพิ่ม)**
     * คิดคะแนนออกมาเป็น 0–100% แล้วหยิบ 5 งานที่คะแนนสูงสุดมาโชว์บนหน้าจอ

### 5. แนวทางการตอบคำถามยอดฮิต (เวลาอาจารย์หรือคนทั่วไปถาม)

#### Q: ทำไมระบบถึงไม่ใช้ ChatGPT หรือ Generative AI ตัวใหญ่ๆ ไปเลยล่ะ?
> **คำตอบ:**  
> "เพราะ Generative AI อย่าง ChatGPT มีข้อจำกัด 3 เรื่องครับ:  
> 1) **ความเร็ว:** ChatGPT ใช้เวลาคิด 3–10 วินาที แต่ระบบของเราใช้เวลาแค่ **3–4 มิลลิวินาที** (เร็วกว่าเกือบ 1,000 เท่า)  
> 2) **ความแม่นยำ:** ChatGPT มีโอกาสมโนคำตอบ (Hallucination) และให้คำตอบไม่เหมือนเดิมในแต่ละครั้ง แต่ระบบของเราคำนวณจากทฤษฎีเซตและสถิติ เป๊ะ 100% ทุกครั้ง  
> 3) **ค่าใช้จ่าย:** ระบบของเราทำงานในเครื่องตัวเองได้ฟรี ไม่ต้องเสียเงินจ่ายค่า API ทุกครั้งที่มีคนกดค้นหาครับ"

#### Q: ทำไมถึงเลือกใช้ Logistic Regression ไม่ใช้ Deep Learning ซับซ้อนๆ?
> **คำตอบ:**  
> "เพราะโครงงานนี้ยึดหลัก **KISS (Keep It Simple, Stupid)** และความโปร่งใสของ AI (Explainable AI) ครับ โมเดล Logistic Regression สามารถเปิดดูค่าน้ำหนักได้ชัดเจนว่าตัดสินใจจากสกิลคำไหน แตกต่างจาก Deep Learning ที่เป็นกล่องดำ (Black Box) ตอบไม่ได้ว่าทำไมถึงแนะนำ และที่สำคัญคือโมเดลนี้กินแรมน้อย ทำงานเร็วมากในระดับเรียลไทม์ครับ"

#### Q: จุดเด่นที่สุดที่ระบบนี้ให้ประโยชน์กับนักศึกษาคืออะไร?
> **คำตอบ:**  
> "คือฟีเจอร์ **Skill Gap Analysis** ครับ เพราะเว็บหางานทั่วไปจะบอกแค่ว่า 'คุณสมบัติไม่ผ่าน' แต่งานวิจัยของเราบอกชัดเจนว่า **คุณขาดทักษะอะไรไปบ้างเป็นชิปสีเทา** ทำให้นักศึกษาสามารถเอาลิสต์นี้ไปจัดตารางเรียนพิเศษ หรือฝึกฝนตัวเองก่อนก้าวเข้าสู่ตลาดแรงงานจริงได้อย่างตรงจุดครับ"
