## 🔴 กลุ่มที่ 3: ข้อห้ามปรับเปลี่ยน (Strict Invariants — ต้องคงไว้ตามเล่มบทที่ 3)
*ส่วนที่ห้ามแตะต้อง เพื่อรักษาความสอดคล้องกับระเบียบวิธีวิจัยที่ได้รับอนุมัติแล้ว*

- [x] **3.1 สูตรการจับคู่ตำแหน่งงาน (Stage 2)**
  - คงสูตร: $\text{Skill Match Percentage} = \frac{|S_{\text{user}} \cap S_{\text{job}}|}{|S_{\text{job}}|} \times 100$ ตามหัวข้อ 3.4.2
  - ไม่เปลี่ยนเป็น Jaccard Similarity หรือ Cosine Similarity ในโค้ดจริง
- [x] **3.2 สูตรความพร้อมในสายอาชีพ (Career Readiness)**
  - คงสูตร: $\text{Career Readiness Percentage} = \frac{|S_{\text{user}} \cap S_{\text{core}}|}{|S_{\text{core}}|} \times 100$ ตามหัวข้อ 3.4.4
- [x] **3.3 สถาปัตยกรรมโมเดลจำแนกสายงาน (Stage 1)**
  - ใช้ TF-IDF Vectorizer + Multi-Class Logistic Regression ($C=0.5$, L2, `class_weight='balanced'`)
  - คุ้มครองคำศัพท์ด้วย Regex `(?u)[a-zA-Z0-9_+#.-]+`

## 🛡️ กลุ่มที่ 4: เช็กลิสต์การเตรียมตัวขึ้นสอบ (Defense Readiness)
*ประเด็นสำคัญสำหรับตอบคำถามคณะกรรมการ*

- [ ] **4.1 เตรียมคำตอบกรณีถามเรื่อง Accuracy (~68.7%)**
  - อธิบายว่าข้อมูลสะท้อนความเป็นจริงของตลาดแรงงาน (Ecological Validity)
  - ย้ำว่าระบบตัดฟิลด์ `Title` ออกจาก Train Data เพื่อป้องกัน Data Leakage ทำให้โมเดลตัดสินใจจากทักษะล้วนๆ
- [ ] **4.2 เตรียมคำตอบกรณีถามเรื่อง Recall ของ G3 ต่ำ**
  - อธิบายว่าตำแหน่ง System Analyst ในตลาดงานปัจจุบันเป็น Hybrid Role ที่ประกาศงานมักระบุทักษะ Coding หรือ UX/UI ปนเข้ามา
  - ชี้แจงว่าระบบมีกลไก Stage 2 (Set Matching) คอยช่วยกรองความสอดคล้องของตำแหน่งงานจริงอีกชั้นหนึ่ง
- [ ] **4.3 ตรวจสอบความพร้อมของเซิร์ฟเวอร์ก่อนเดโม**
  - ทดสอบรัน `python src/validate.py` (ต้องผ่านครบ 5 มิติ)
  - ทดสอบเริ่มเซิร์ฟเวอร์ผ่าน `run.bat` หรือ `python src/main.py`
  - ตรวจสอบหน้าเว็บที่ `http://127.0.0.1:8000/ui` ว่าจับคู่ทักษะและแสดงผลการ์ดงานได้ถูกต้อง
